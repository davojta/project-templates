# Docs Guidelines

Applies to everything in `docs/`.

- **Be laconic.** Short bullets, not paragraphs. One idea per line.
- **Skip the trivial.** Don't explain what the code, `--help`, or a library's own docs already make obvious.
- **Focus on what matters:** non-obvious decisions, trade-offs, constraints, risks, and anything that breaks if ignored.
- **State the "why", not the "what".** The code shows what; docs record why and what was rejected.
- **No duplication.** Link to `AGENTS.md`, `ARCHITECTURE.md`, or code instead of restating them.

## ADRs (`docs/adr/NNN-title.md`)

Sections: **Status/Date**, **Context** (the problem), **Decision** (choice + key reasons + rejected options), **Consequences** (constraints and risks only).
